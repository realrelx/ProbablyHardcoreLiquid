# 喷壶（Spray Bottle）设计与实现说明

版本 0.8.0 · 对应 `src/Items/Spray.cs`

## 1. 物品规格

| 项 | 值 | 位置 |
|---|---|---|
| 物品 ID | `dsc_spray_bottle` | `Spray.SprayId` |
| 格子 | 1×2（贴图 74×74 px，按 `gridSize≈36.57` 取 2 格） | `Textures/Items/spray_*.png` |
| 容量 | 1000 ml | `Spray.CapacityMl` |
| 基础价 | 80 信用点（可配） | `spray_price` |
| 类型 | `TOOL`，`IMPORTANT_TAG` 关闭 | `CreateSprayCore` |
| 液体容器 | `WaterHelper.InitLiquidContainerItem(item, 1000, price, false,false,false,false,0)` | 同上 |

**能力限制（刻意做成这样）**

- 拖到排水口 / 水槽：只倒掉（`WaterHelper.EmptyContainer`），不产生转移。
- 拖到另一个液体容器：清洗（本文 §2），**不把壶里液体整份倒进目标**。
- 拖到其他物品：`CanSprayTarget` 返回 false，无交互。
- 因此模组**不提供**"把喷壶当水桶"的路径；想搬家只能靠原版容器。

## 2. "永远洗不干净"的数学模型

容器有固有残留 `c`（由残留系统给出：`min(容量 × 残留比例 × 粘度因子, 残留上限)`，至少 1000 µl）。
先用一种溶液 A 装到 `c`，再用总量 `M` 的溶液 B 清洗，分 `n` 次、每次 `M/n`，每次混匀后倒空到只剩 `c`：

```
P_n = (1 + M/(n·c))^(-n)
lim P_n (n→∞) = e^(-M/c)
```

最终组成（各组分独立成立）：

```
C_final = e^(-M/c) · A + (1 - e^(-M/c)) · B
```

默认 `M/c = 3` → 残留 `e^-3 = 4.98%`。`M/c = 10` → 0.0045%（近似洗干净，但永不为 0）。

**实现取舍**：不模拟 n 次往返，直接落 n→∞ 的闭式解（`Spray.Rinse`）：
1. 读目标成分向量 `A` 与体积 `Va`、喷壶成分向量 `B` 与体积 `Vb`；
2. `p = e^(-k)`，`k = min(rinse_ratio, Vb/c)`；
3. `Remove(target, Va)` 倒空目标（等于用户"倒掉超过 c 的部分"）；
4. 按 `c·(p·A/Va + (1-p)·B/Vb)` 逐成分 `AddLiquid` 回填（四舍五入，尾差补给最大成分）；
5. `Remove(spray, k·c)` 按比例扣喷壶。

这样一次交互 = 用户描述的整个极限过程，且不依赖 20 ml 小股循环，行为可预测、可测试。

## 3. 获取方式

| 来源 | 条件 | 内容 |
|---|---|---|
| 化学家开局 | `PlayerStore.Instance.IsChemistStart()`（startType==6）且 `spray_start_gift` | 一把满壶；水质由 `spray_gift_fill` 决定：`pure` 纯水 / `high_quality` 优质水 / `base` 基础水 |
| 化学商人 / 博士货架 | 每次生成客户时按 `spray_doctor_prob`（默认 35%） | **空壶**一把 |
| 化学家权重 | `spray_chemist_weight`（默认 10，百分数） | 提高化学家客户出现概率 |

礼装一次性（`_giftGiven`），读档不重复发放；`onLoaded += RepairSpray` 负责补形状/贴图。

## 4. 配置项（ModConfig，默认值为"用户看到的默认难度"）

| key | 默认 | 含义 |
|---|---|---|
| `spray_enabled` | true | 喷壶总开关 |
| `spray_rinse_ratio` | 3 | 清洗倍率 M/c；`0` 表示禁止清洗（拖上去报"洗不了"） |
| `spray_start_gift` | true | 化学家开局送礼 |
| `spray_gift_fill` | `pure` | 礼装水质：pure / high_quality / base |
| `spray_chemist_weight` | 10 | 化学家客户出现权重（%） |
| `spray_doctor_prob` | 0.35 | 商人货架出现空壶概率 |
| `spray_price` | 80 | 基础售价（信用点） |

## 6. 与残留系统的关系

`Spray.Rinsing` 为真期间，`Patches.CaptureArg` 直接返回 `null`，10 个液体出口补丁全部跳过结算——清洗期间的体积变化由 `Rinse` 自己管理，避免"洗一次又按残留再扣一次"的双重扣减。

## 7. 与 DeepSpaceChemistry 的叠加

两者都补 `WaterHelper.TransferLiquid` 等出口。Harmony 允许多个补丁共存（各自 prefix/postfix 独立），但要保证：
- 我们的 patch ID 不带 `dse.` 前缀（SEC-04）；
- 若对方在 prefix 返回 false 阻断原方法，我们的 postfix 仍会跑，`ResidueLogic.Apply(null)` 首行判空安全；
- 同时启用时优先实机验证"倾倒 → 残留"只扣一次。
